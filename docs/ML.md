# レーン配置を生成する GRU

クロス・ノーツのプロセカ風モードで、**どのノーツをどのレーン（D / F / J / K）に置くか**を
決めている機械学習モデルの中身。

学習し直す手順は [TRAINING.md](TRAINING.md)。

---

## なぜ学習なのか

元の実装は 1 行だった。

```python
column = random.randint(0, 3)     # 音楽とも運指とも無関係な乱数
```

これだと、同じリズムでも配置がばらばらで、押しにくいだけの譜面になる。

かといって、**レーンは音高の決定的な関数ではない**。同じ旋律・同じリズムでも、
譜面制作者は曲の文脈や直前の運指を見て違う鍵を選ぶ。
左右交互に振る、トリルにする、階段状に流す——こうした**人手の癖**は、
十数行のルールでは書き下せない。

そこで「前の記号から次の記号を予測する」枠組み（偽文生成と同じ）を、
記号＝文字ではなく**記号＝レーン**に置き換え、
教師をルールではなく **osu!mania 4K の実譜面**にした。

---

## 入力と出力

| | 次元 | 内容 |
|---|---|---|
| **入力** | 7 | 前ステップのレーン分布 (4) + 直前のノーツ間隔バケット one-hot (3) |
| **出力** | 4 | そのステップのレーン分布 |

**音高は一切使わない。** 使うのは「直前にどこを叩いたか」と「前の音からどれだけ空いたか」だけ。
だからゲーム側は、MIDI から作った**ノーツ時刻列[秒]**を渡すだけでよい。

### 和音の扱い

同時押しは捨てずに、鳴る全レーンへ均等な確率を割り当てる。

```
レーン1と3の同時押し  →  [0, 0.5, 0, 0.5]
```

正解が one-hot ではなく**分布**になるので、損失は `categorical_crossentropy` を使う。

### 間隔バケット

音符間隔[ms]を3つ（短 / 中 / 長）に区切る。境界は学習データから決まり、
`osu_dataset.npz` の `gap_edges` に保存される（例: `[86.0, 120.0]`）。

推論時も同じ境界を使う必要があるため、**モデルと npz はセットで扱う**。

---

## モデル構造

```
Input(batch, time, 7)
  → GRU(48, return_sequences=True)
  → GRU(48, return_sequences=True)
  → TimeDistributed(Dense(4, activation="softmax"))
```

- 損失: `categorical_crossentropy`
- 最適化: Adam
- 系列長: 24 ステップ

---

## 生成（自己回帰）

学習時は「実譜面の前レーン」を入力に与えられるが、**新しい曲には正解が無い**。
そこで推論では、モデル自身の直前の出力を次ステップの入力に戻す。

```
開始トークン（前レーン無し・間隔=長）
  → レーン予測 ─┐
      ↑          │
      └──────────┘  1音ずつ、時刻列の最後まで
```

`chart_ai_osu.py` はこの生成のために、学習済みモデルの重みを
**同じ構造の stateful モデルへ移し替えている**。
1ステップ推論のたびに内部状態を持ち越すので、n 音の生成が O(n) で済む
（毎回系列全体を流し直すと O(n²) になる）。曲の先頭で `reset_states()` する。

### temperature

出力確率をそのまま使うか、鋭く / なだらかにするかの調整。

```python
logits = np.log(proba) / temperature
lane   = sample(logits)
```

| 値 | 挙動 |
|---|---|
| `0.0` | サンプリングせず `argmax`。最尤で規則的、単調になりやすい |
| `1.0` | 学習した確率を無加工で使う。**人手の譜面に最も近い** |
| `> 1.0` | 分布がなだらかになり、崩れた配置が混ざる |

ゲームでは生成前の調整画面で 0.0〜1.5 の範囲から選ぶ。

## 評価

`train_osu_GRU.py` は、**次レーン的中率**——予測したレーンがその時刻に実在するか
（和音ならどちらを当てても的中）——を検証データで測る。

比較対象として **1次マルコフ**のベースラインも同時に出す。
これは「直前のレーンだけ」から最頻の次レーンを返すモデルで、
つまり**間隔も長期の文脈も使わない**。

GRU がこれを上回ってはじめて、
「間隔と文脈を見て次のレーンを決めている」と言える。

学習曲線（loss / accuracy の train・validation）は
`train/osu_learning_curve.png` に出力される。
