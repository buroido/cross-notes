# 学習し直す

レーン配置を生成する GRU を、自分で用意した実譜面から学習し直す手順。

**遊ぶだけならこの作業は不要**（学習済みモデルが `play/` に同梱されている）。
やる価値があるのは、教師にする譜面を増やしたい / 別の傾向の譜面を学ばせたい / ハイパーパラメータを変えたいとき。

モデルが何をどう学んでいるかは [ML.md](ML.md) を参照。

---

## 全体の流れ

```
train/osu_data/  (実譜面 .osu)
      │  python parse_osu.py
      ▼
play/osu_dataset.npz        学習データ (X, Y, gap_edges)
      │  python train_osu_GRU.py
      ▼
play/osu_lane_model.keras   学習済みモデル  ← ゲームがこれを読む
train/osu_learning_curve.png 学習曲線
```

学習スクリプトは `train/` に、**成果物はゲームが読む `play/` に出る**ので、
学習し終わったらそのまま `cd ../play && python game.py` で反映を確認できる。

---

## 1. 教師データを置く

**このリポジトリに譜面は含まれていない。** `train/osu_data/` に `.osu` を自分で置く。

```
train/
└── osu_data/
    ├── set_01/
    │   ├── アーティスト - 曲名 (作者) [Easy].osu
    │   ├── アーティスト - 曲名 (作者) [Hard].osu
    │   └── ...
    ├── set_02/
    └── ...
```

- **サブフォルダは再帰的に探索される**ので、`.osu` が下にあれば階層は自由
- `.osz`（osu! の配布形式）は zip。展開して中の `.osu` を置く
- 音源・画像・動画は使わないので入れなくてよい（`.gitignore` 済み）

### 採用される譜面の条件

`parse_osu.py` が自動で振り分ける。条件に合わないものは黙って捨てられる。

| 条件 | 理由 |
|---|---|
| `Mode: 3`（osu!mania） | 落ちものリズムゲーム形式であること |
| **4鍵** (`CircleSize: 4`) | ゲームが D / F / J / K の4レーンだから |
| ノーツが十分ある | 系列長 24 に満たない譜面は使えない |

同一譜面の重複も除外される。実行すると採用・除外・重複の件数が表示されるので、
**採用数が 0 なら置き場所か鍵数が違う**。

## 2. 学習データを作る

```
cd train
python parse_osu.py
```

やっていること:

1. `osu_data/` 以下の `.osu` を走査し、mania 4K だけ採用
2. `[HitObjects]` から `(時刻ms, レーン)` を取り出す（`lane = x * 4 // 512`）
3. 同時押し（和音）は捨てず、鳴る全レーンに等しい確率を割り当てる
   （例: レーン1と3の同時押し → `[0, 0.5, 0, 0.5]`）
4. 音符間隔を3つのバケット（短 / 中 / 長）に区切る。境界は**データから決まる**
5. 長さ 24 ステップの系列に切って `../play/osu_dataset.npz` に保存

出力例:

```
[DATASET] X=(1475, 24, 7)  Y=(1475, 24, 4)   (入力次元 FEAT_DIM=7)
saved: ...\play\osu_dataset.npz
```

抽出例のテーブルも表示されるので、レーン分布と間隔バケットが妥当か目視できる。

## 3. 学習する

```
cd train
python train_osu_GRU.py
```

既定のハイパーパラメータ（`train_osu_GRU.py` 冒頭の `PARAMETER(S)` で変更できる）:

| 項目 | 値 |
|---|---|
| GRU ユニット数 `N_UNITS` | 48（2層） |
| エポック数 `EPOCHS` | 30 |
| バッチサイズ `BATCH_SIZE` | 64 |
| 検証データ比率 `VAL_RATIO` | 0.2（系列単位でシャッフルして分割） |
| 乱数シード `SEED` | 1 |
| 損失 | `categorical_crossentropy`（正解がレーン**分布**なので） |
| 最適化 | Adam |

出力されるもの:

- `../play/osu_lane_model.keras` … 学習済みモデル（**上書きされる**）
- `osu_learning_curve.png` … loss / accuracy の学習曲線（train と validation）

### 結果の見かた

**次レーン的中率**（予測したレーンがその時刻に実在したか。和音はどちらを当てても的中）が、
GRU と **1次マルコフのベースライン**の両方について表示される。

マルコフは「直前のレーンだけ」から最頻の次レーンを返すモデルなので、
**GRU がこれを上回っていなければ、間隔や長期の文脈を活かせていない**ことになる。
上回らないときは教師譜面を増やすか、`N_UNITS` / `EPOCHS` を見直す。

学習曲線で validation loss が途中から上がっていれば過学習。`EPOCHS` を減らす。

## 4. 反映を確認する

```
cd ../play
python chart_ai_osu.py
```

等間隔ノーツ20個に対するレーン列が出る。`temperature=0` の行が
同じレーンの連打だらけなら学習がうまくいっていない。

問題なければゲームで確認する:

```
cd play
python game.py
```

プロセカ風モードを選び、temperature 1.0 で生成すれば新しいモデルの譜面が遊べる。

---

## 注意

- `parse_osu.py` と `train_osu_GRU.py` は **`train/` をカレントディレクトリにして**実行する
- `train_osu_GRU.py` は `play/osu_lane_model.keras` を**上書きする**。
  同梱の学習済みモデルを残したいなら先にコピーを取っておく
- `osu_dataset.npz` は学習データであると同時に、**推論時の間隔バケット境界の供給元**でもある。
  学習データを作り直したら、モデルと npz は**必ずセットで**使う
