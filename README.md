# クロス・ノーツ

**異なったインターフェースによって対戦可能な音楽ゲーム**

手持ちの MIDI ファイルを読み込んで譜面を自動生成し、
「プロセカ風の4レーン落ちゲー」と「太鼓の達人風の2種叩き分け」という
操作感の違う2つのスタイルで遊べる音楽ゲームです。
2人プレイでは**この2つを混ぜて対戦できる**のが最大の特徴で、
片方が4レーン・もう片方が太鼓、という噛み合わない勝負が成立します。

Python + pygame で作られています。曲は MIDI 音源で鳴らすため、MIDI さえあれば何でも譜面になります。

```
python game.py     # play/ フォルダで実行してください
```

初回セットアップと必要ファイルの置き方は **[docs/SETUP.md](docs/SETUP.md)** をご覧ください。

## なぜ作ったか

音楽ゲームは、スマートフォンアプリ（『プロジェクトセカイ カラフルステージ！ feat. 初音ミク』
『DEEMO』など）の普及によって、幅広いユーザ層が遊ぶジャンルになりました。
実際に楽器を演奏する感覚で遊べる作品（『GITADORA GALAXY WAVE』『太鼓の達人』など）、
ダンスをしながら遊ぶ作品（『DanceDanceRevolution』）、
シューティングと融合した作品（『オンゲキ』）というように、形も多様化しています。

一方で、このジャンルには2つの課題があると考えました。

### 課題1: ライトユーザにとって飽きられやすい

音楽ゲームは、タイミングよく叩けたかをスコア化し、そのスコアで競う
**スコアアタック型**のゲームシステムが主流です。
このシステムである以上、ユーザはよりよいスコアを目指すことを目標として設定する傾向が強く、
遊び方が自己ベストの更新に寄っていきます。
気軽に楽しみたいライトユーザにとっては、飽きやすい構造だといえます。

### 課題2: 好みの違うユーザ同士が交流しにくい

スコアアタック型であることから、一つの作品に特化して遊ぶヘビーユーザが生まれやすく、
その結果として他の作品に触れる機会が減りがちです。
さらに、異なる作品を好む、あるいは得意とするユーザ同士が一緒に遊ぼうとしても、
それぞれが楽しめるゲームを同時にプレイすることが難しいため、交流の機会が限られてしまいます。

### 本作の答え

これらの課題の解決策として、本作では**異なるインターフェースを用いて対戦可能な音楽ゲーム**を提案します。

| 課題 | 本作での解決 |
|---|---|
| 好みの違うユーザ同士が交流しにくい | プレイスタイルを **P1・P2 が別々に選べる**ようにしました。落ちゲーが得意な人と太鼓が得意な人が、同じ曲を**それぞれ慣れた操作のまま**、同じ勝負として遊べます |
| 腕前の差で一緒に遊びにくい | 難易度も P1・P2 で別々に選べます。実力差があっても同じ曲で並んで遊べます |
| スコアアタックに寄って飽きやすい | 競う項目を**スコア以外にも**用意しました。最大コンボ数・Just 数・合計 Hit 数・サドンデスから選べるほか、勝敗をつけない「仲良くプレイする」もあります |
| 遊べる曲が固定されて飽きやすい | 手持ちの **MIDI ファイルがそのまま譜面になります**。レーン配置は実譜面を学習した GRU が決めるため、乱数配置と違って初見の曲でも叩ける譜面になります |

「同じスコアを競う」のではなく「**違う遊び方のまま、同じ土俵に乗る**」ことが、
このゲームの狙いです。

## 特徴

### 1. 2つのプレイスタイル

| モード | 操作 | 内容 |
|---|---|---|
| **プロセカ風** | 4レーン (D / F / J / K) | 上から降ってくるノーツを、落ちてきたレーンのキーで叩きます |
| **太鼓の達人風** | 2種類 (内側 F・J = ドン / 外側 D・K = カッ) | 右から流れてくるノーツを、色に応じて叩き分けます |

判定は **JUST / GOOD / MISS** の3段階です。判定ラインからのズレが小さいほど JUST になります。
プレイ中はコンボ・最大コンボ・JUST 数・GOOD 数が表示され、リザルトではこれに加えて
MISS 数と精度（JUST を1点、GOOD を0.5点として全ノーツで割った割合）、
そこから決まるランク（S 95% / A 90% / B 80% / C 70% / D 50% 以上）が出ます。

プレイ中は **ESC** でリザルトへ抜け、**R** でタイトルへ戻れます。**F11** で全画面に切り替わります。

### 2. インターフェースをまたいだ対戦

2人プレイでは、P1 と P2 が**それぞれ別のスタイルと難易度**を選べます。
同じ曲・同じ音を、片方は4レーンで、片方はドン/カッで捌くことになります。

- **P1**: A / S / D / F
- **P2**: L / ; / : / ]

競う項目も選択できます。

| 項目 | 勝敗の決め方 |
|---|---|
| 仲良くプレイする | 勝敗なし。並んで叩くだけです |
| 最大コンボ数 | 最大コンボが多いほうが勝ちです |
| JUST 数 | JUST 判定が多いほうが勝ちです |
| 合計 Hit 数 | JUST + GOOD が多いほうが勝ちです |
| サドンデス | HP 20 スタート。MISS で減り、先に 0 になったほうが負けです |

ソロには **ノーマル** と **HP モード**（MISS で HP が減り、0 で強制終了）があります。

### 3. 好きな MIDI がそのまま譜面になる

`play/music/` に置いた `.mid` が選曲画面に並びます。譜面は実行時に生成されます。

- MIDI の Note On を時刻[秒]に変換し、**平均音高以上の音**＝主旋律だけをノーツにします
- 難易度 Easy / Normal / Hard は**同時刻とみなす幅**（0.5 / 0.15 / 0.1 秒）を表し、
  狭いほど音を拾うためノーツが増えます。難易度選択画面には実際のノーツ数が出ます
- 曲そのものは `pygame.midi` の MIDI 出力で鳴らしています

### 4. レーン配置を機械学習で決める（AI 譜面生成）

**このゲームで機械学習を使っているのはここです。**

4レーンのどのキーに置くかは、元は `random.randint(0, 3)` の完全な乱数でした。
つまり配置が音楽とも運指とも無関係で、「押しにくいだけの譜面」になっていました。

そこで、**人間が作った実譜面（osu!mania 4K）を教師にした GRU** に置き換えました。
「直前に叩いたレーン」と「前の音からの間隔」から次のレーンを予測し、
それを1音ずつ自分の出力に戻していきます（自己回帰生成）。

その結果、ルールで書き下すのが難しい**人手の癖**——左右交互打ち、トリル、
階段——が配置に現れるようになり、乱数配置より格段に叩ける譜面になりました。

プロセカ風モードを選ぶと、生成前に **temperature 調整画面**が入ります。

| temperature | 生成される譜面 |
|---|---|
| `0.0` | 最尤です。規則的で読みやすい反面、単調になります |
| `1.0`（既定） | 学習した確率をそのまま使います。**人手の譜面に最も近い設定です** |
| `1.5` | 揺らぎが大きく、崩れた配置が混ざります |

↑↓←→ で調整し、Enter で決定します。決定後、生成中はロード画面が表示されます。

モデルの構造・学習データ・入出力の詳細は **[docs/ML.md](docs/ML.md)** をご覧ください。
自分で学習し直す手順は **[docs/TRAINING.md](docs/TRAINING.md)** にまとめています。

## 操作方法

### メニュー

| 画面 | 操作 |
|---|---|
| タイトル | `Enter` でスタートします |
| 曲選択 | `↑` `↓` で選択し、`Enter` で決定します |
| 各種モード選択 | 数字キー `1` `2` … で選びます |
| temperature 調整 | `↑` `→` で上げ / `↓` `←` で下げ / `Enter` で決定します |

### プレイ中

| | プロセカ風 | 太鼓の達人風 |
|---|---|---|
| **ソロ** | `D` `F` `J` `K`（左から順に） | ドン = `F` `J` / カッ = `D` `K` |
| **2P - P1** | `A` `S` `D` `F` | ドン = `S` `D` / カッ = `A` `F` |
| **2P - P2** | `L` `;` `:` `]` | ドン = `;` `:` / カッ = `L` `]` |

`Esc` で中断できます。リザルト画面では `R` でタイトルに戻り、`Esc` で終了します。

## ゲームの流れ

```
タイトル
  └ 曲選択（play/music/ の .mid）
      └ 1人 / 2人
          └ プレイスタイル選択（プロセカ風 / 太鼓の達人風） ※2人なら P1・P2 別々
              └ 難易度選択（Easy / Normal / Hard）
                  └ temperature 調整   ← プロセカ風を選んだときだけ
                      └ 譜面生成（GRU 推論・ロード画面）
                          └ ソロモード選択 / 対戦項目選択
                              └ プレイ → リザルト
```

## リポジトリ構成

```
.
├── play/                    遊ぶのに必要なもの一式
│   ├── game.py                  ゲーム本体（ここで python game.py）
│   ├── chart_ai_osu.py          学習済みモデルでレーンを生成する推論ヘルパ
│   ├── osu_lane_model.keras     学習済み GRU
│   ├── osu_dataset.npz          学習データ（推論時は間隔バケット境界を参照）
│   ├── ドン.wav / カッ.wav / suzu.mp3   効果音
│   └── music/                   ★ 遊ぶ曲(.mid)をご自分で置いてください
│
├── train/                   学習し直すときだけ使います
│   ├── parse_osu.py             osu_data/ の .osu → 学習データ
│   ├── train_osu_GRU.py         学習データ → 学習済みモデル
│   ├── osu_learning_curve.png   学習曲線
│   └── osu_data/                ★ 教師にする実譜面(.osu)をご自分で置いてください
│
└── docs/
    ├── SETUP.md             インストールとファイルの置き方
    ├── TRAINING.md          モデルを学習し直す手順
    └── ML.md                モデルの中身
```

★ の2つは第三者の著作物にあたるため、このリポジトリには**含めていません**。
遊ぶだけであれば `play/music/` に MIDI を入れるだけで済みます。学習済みモデルは同梱しています。

## 動作環境と制限

### 動作確認環境

| | バージョン |
|---|---|
| OS | Windows 11 |
| Python | 3.11.9 |
| pygame | 2.6.1 |
| mido | 1.3.3 |
| numpy | 2.3.2 |
| tensorflow | 2.21.0 |
| tf-keras | 2.21.0 |
| matplotlib | 3.10.8（学習し直すときのみ） |

ライブラリは `pip install -r requirements.txt` でまとめて入ります。
`tensorflow` と `tf-keras` は**同じマイナーバージョンで揃えてください**
（`TF_USE_LEGACY_KERAS=1` で旧 Keras API を使って推論しているためです）。

### 制限

- フォントに Windows のシステムフォント **meiryo** を使うため、Windows が前提です
- 曲の再生に **MIDI 出力デバイス** を使います（Windows 標準の GS Wavetable Synth など）
- **曲中で BPM が変わる MIDI には対応していません**（起動時に検出して終了します）
- MIDI トラック中の楽器は先頭2つまでを対象としています
